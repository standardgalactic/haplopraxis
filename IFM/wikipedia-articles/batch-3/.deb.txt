   Debian software package format

   CAPTION: Debian package

   [85][64px-Application-x-deb.svg.png]
   The [86]GNOME icon for deb files
   (showing the [87]Debian logo on a package)
   [88]Filename extension
   .deb, .udeb
   [89]Internet media type
   application/vnd.debian.binary-package^[90][1]
   Developed by [91]Debian
   Type of format [92]Package management system
   [93]Container for [94]Software package
   Extended from [95]ar archive, [96]tarball

   Website [97]deb format specification

   deb is the format, as well as [98]filename extension of the
   [99]software package format for the [100]Debian [101]Linux distribution
   and [102]its derivatives.

Design

   [[103]edit]

   [104][220px-Gdebi.png] GDebi installing a .deb package

   Debian packages are standard [105]Unix [106]ar archives that include
   two [107]tar archives. One archive holds the control information and
   another contains the installable data.^[108][2]

   [109]dpkg provides the basic functionality for installing and
   manipulating Debian packages. Generally end users don't manage packages
   directly with [110]dpkg but instead use the [111]APT package management
   software or other [112]APT front-ends such as [113]aptitude
   ([114]nCurses) and [115]synaptic ([116]GTK).^[117][3]

   Debian packages can be converted into other package formats and vice
   versa using [118]alien, and created from source code using
   [119]checkinstall or the Debian Package Maker.^[120][4]

   Some core Debian packages are available as udebs ("micro debs"), and
   are typically used only for bootstrapping a Debian installation.
   Although these files use the udeb filename extension, they adhere to
   the same structure specification as ordinary deb files. However, unlike
   their deb counterparts, udeb packages contain only essential functional
   files.^[121][5] In particular, documentation files are normally
   omitted. udeb packages are not installable on a standard Debian system,
   but are used in [122]Debian-Installer.

Implementation

   [[123]edit]

   [124][220px-Deb_File_Structure.svg.png] Diagram showing an example file
   structure of a .deb file[125]
   [220px-Frhed_hex_editor_displaying_deb_package.png] [126]Frhed hex
   editor displaying the raw data of a Debian package

   Prior to Debian 0.93, a package consisted of a file header and two
   concatenated [127]gzip archives.^[128][6] Since Debian 0.93, a deb
   package is implemented as an [129]ar archive.^[130][7] This archive
   contains three files in a specific order:^[131][8]^[132][9]
    1. debian-binary - A text file named debian-binary containing a single
       line giving the package format version number. (2.0 for current
       versions of Debian).^[133][9]
    2. control archive - A tar archive named control.tar contains the
       maintainer scripts and the package meta-information (package name,
       version, dependencies and maintainer). Compressing the archive with
       [134]gzip or [135]xz and [136]zstd is supported. The file extension
       changes to indicate the compression method.^[137][9]^[138][2]
    3. data archive - A tar archive named data.tar contains the actual
       installable files. Compressing the archive with [139]gzip,
       [140]bzip2, [141]lzma or [142]xz and [143]zstd is supported. The
       file extension changes to indicate the compression
       method.^[144][9]^[145][2]

Control archive

   [[146]edit]

   The control archive contents can include the following files:
     * control contains a brief description of the package as well as
       other information such as its
       dependencies.^[147][10]^[148][11]^[149][12]^[150][13]
     * md5sums contains [151]MD5 [152]checksums of all files in the
       package in order to detect corrupt or incomplete files.^[153][14]
     * conffiles lists the files of the package that should be treated as
       configuration files. Configuration files are not overwritten during
       an update unless specified.^[154][15]
     * preinst, postinst, prerm and postrm are optional scripts that are
       executed before or after installing or removing the
       package.^[155][15]^[156][16]
     * config is an optional script that supports the [157]debconf
       configuration mechanism.^[158][17]
     * shlibs list of shared library dependencies.^[159][18]^[160][19]

Signed packages

   [[161]edit]

   Debian-based distributions support [162]OpenPGP signature verification
   of signed Debian packages, but most (if not all) have this feature
   disabled by default.^[163][20] Instead packages are verified by signing
   the repository metadata (i.e. Release files). The metadata files in
   turn include checksums for the repository files as a means to verify
   authenticity of the files.^[164][21]^[165][22] Currently there are two
   different implementations for signing individual packages. The first is
   done via the debsigs / debsig-verify toolset, which is supported by
   [166]dpkg.^[167][20]^[168][23] The second is done through the dpkg-sig
   program which is not supported by [169]dpkg, so the packages have to be
   manually checked with the dpkg-sig
   program.^[170][20]^[171][24]^[172][25]^[173][26] Both formats add new
   sections to the [174]ar archive to store the signature information, but
   the formats are not compatible with one another.^[175][20] Neither of
   the modifications to the package format are listed in the official
   Debian handbook or [176]man page about the binary package
   format.^[177][27]^[178][8]

Adoption

   [[179]edit]

     * Debian packages are used in distributions [180]based on Debian,
       such as, [181]Linux Mint (LMDE),^[182][28]^[183][29] [184]KDE neon,
       [185]Ubuntu and [186]many others.
     * [187]Fink, a port of [188]dpkg and [189]APT to [190]macOS, uses deb
       packages.^[191][30]^[192][31]
     * [193]Nexenta OS, a discontinued OS based on [194]OpenSolaris,
       included Debian package management software and the use of deb
       packages.
     * [195]Debian GNU/kFreeBSD, an OS that uses a GNU based [196]userland
       and the FreeBSD kernel.
     * [197]Debian GNU/Hurd.
     * Some [198]jailbroken iOS devices (iPhones, iPads and
       iPods).^[199][32]^[200][33]
     * [201]Ipkg and [202]Opkg, which both use .ipk packages that resemble
       [203]Debian's [204]dpkg

     * [205]Termux, which is a [206]GNU environment for [207]Android.
