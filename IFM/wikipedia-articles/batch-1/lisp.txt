   CAPTION: *Lisp (StarLisp)

   [65]Paradigms [66]Multi-paradigm: [67]functional, [68]procedural,
   [69]reflective, [70]meta, [71]parallel
   Family [72]Lisp
   [73]Designed by Cliff Lasser, [74]Steve Omohundro
   [75]Developer [76]Thinking Machines Corporation
   First appeared 1986; 39 years ago (1986)
   [77]Typing discipline [78]Dynamic, [79]strong
   [80]Scope [81]Static, lexical
   Implementation language [82]Common Lisp
   [83]Platform [84]Connection Machine
   [85]OS Connection Machine
   Influenced by
   [86]Lisp, [87]Common Lisp
   Influenced
   [88]C*

   *Lisp (or StarLisp) is a [89]programming language, a [90]dialect of the
   language [91]Lisp.^[92][1] It was conceived of in 1985 by two employees
   of the [93]Thinking Machines Corporation, Cliff Lasser and [94]Steve
   Omohundro, as a way to provide an efficient yet high-level language for
   programming the nascent [95]Connection Machine (CM).

History

   [[96]edit]

Prelude

   [[97]edit]

   At the time the Connection Machine was being designed and built, the
   only language being actively developed for it was an [98]assembly-level
   language named PARIS (Parallel Instruction Set). It became evident that
   a better way to program the machine was needed, and quickly. Waiting
   for the completion of Connection Machine Lisp (CM Lisp), an
   implementation of the [99]very high-level programming language
   [100]Lisp with [101]parallel computing extensions) was not an option.
   CM Lisp had been proposed by [102]Danny Hillis, and development was
   expected to continue for several more years.

Development

   [[103]edit]

   A *Lisp [104]interpreter was initially developed. It became apparent
   quickly that a *Lisp [105]compiler, translating *Lisp into [106]Lisp
   and PARIS, would be needed to attain the giga[107]FLOPS speed that was
   attainable in theory by a Connection Machine. The *Lisp compiler was
   written by Jeff Mincy and was first released in 1986. An application
   achieving more than two gigaFLOPS, a helicopter wake simulator, was
   developed by Alan Egolf, then an employee of [108]United Technologies,
   and J. P. Massar, a Thinking Machines employee, in 1987.^[109][2]

   A *Lisp Simulator, an [110]emulator meant to run *Lisp code on
   standard, non-parallel machines, was developed at the same time by J.
   P. Massar. This simulator still exists,^[111][3] and was ported to
   [112]American National Standards Institute (ANSI) [113]Common Lisp (CL)
   in 2001. An older version written in the original CL, exists in the
   [114]Carnegie Mellon University (CMU) [115]artificial intelligence (AI)
   repository.^[116][4]

   Later versions of *Lisp, involving significant upgrades to its
   functions and performance, were worked on by Cliff Lasser, Jeff Mincy,
   and J. P. Massar through 1989. *Lisp was implemented on the Thinking
   Machines CM5 circa 1990–1991 by J. P. Massar and Mario Bourgoin.

Implementation

   [[151]edit]

   StarLisp was written on [152]Common Lisp (CL), and thus had the full
   power of CL behind it. To use a Connection Machine, one needed a host
   or front-end. To use *Lisp, that front-end had to run CL.
   [153]Symbolics' machines using [154]Genera and [155]Sun Microsystems
   workstations running [156]Lucid Inc.'s Lucid Common Lisp were both used
   to operate *Lisp.

   StarLisp operated on Parallel Variables (PVARS). These represented
   Connection Machine memory, and were essentially [157]vectors: one
   element per CM processor (or virtual processor).

   StarLisp consisted of standard operations on PVARS, like vector
   addition and multiplication, along with communication primitives that
   essentially reordered the elements of a PVAR using the CM's
   communication hardware to optimally route the data.
