   Internet top-level domain

   CAPTION: arpa

   Introduced January 1, 1985; 40 years ago (1985-01-01)
   [89]TLD type Infrastructure domain
   Status Active
   [90]Registry [91]IANA
   Sponsor [92]Internet Architecture Board
   Intended use A temporary TLD to facilitate the transition from
   [93]ARPANET to the DNS.
   Actual use Internet infrastructure such as reverse DNS lookup.
   Registration restrictions No domain registrations possible, new
   subdomains rarely added
   Structure Second-level domains used for various functions related to
   Internet infrastructure as defined by RFCs.
   Documents
   [94]RFC [95]3172; [96]RFC [97]9120
   Dispute policies None
   [98]DNSSEC Yes
   Registry website [99]IANA .arpa info

   The domain name arpa is a [100]top-level domain (TLD) in the
   [101]Domain Name System (DNS) of the [102]Internet. It is used
   predominantly for the management of technical network infrastructure.
   Prominent among such functions are the subdomains in-addr.arpa and
   ip6.arpa, which provide namespaces for [103]reverse DNS lookup of
   [104]IPv4 and [105]IPv6 addresses, respectively.

   The name originally was the [106]acronym for the [107]Advanced Research
   Projects Agency (ARPA), the funding organization in the United States
   that developed the [108]ARPANET, the precursor of the Internet. It was
   the first domain defined for the network in preparation for a
   hierarchical naming system for the delegation of authority, autonomy,
   and responsibility. It was originally intended only to serve in a
   temporary function for facilitating the systematic naming of the
   ARPANET computers. However, it became practically difficult to remove
   the domain after infrastructural uses had been sanctioned. As a result,
   the name was redefined as the [109]backronym Address and Routing
   Parameter Area.

   Domain-name registrations in arpa are not possible, and new subdomains
   are infrequently added by the [110]Internet Engineering Task Force.

Purpose

   [[111]edit]

   Each computer using the [112]Internet Protocol is identified by a
   numerical [113]IP address for identification and location
   addressing.^[114][1] Each host is also assigned a more memorable
   [115]hostname, which often relates to the purpose or ownership of the
   host, and is used more conveniently in user interaction with network
   functions, such as when connecting to or accessing a resource.
   Originally, the mapping between names and addresses was a cumbersome
   mechanical process using lookup tables distributed as computer files
   between network administrators. The [116]Domain Name System (DNS)
   solved this inefficiency by automating the lookup function with a
   hierarchical naming system using domain names. When a user requests a
   network service using a domain name, the protocol implementation
   (protocol stack) translates the name to an address that can be used to
   reach a remote host.

   This naming function, often called forward resolution, was the original
   purpose of the top-level domain "ARPA". It was the first domain defined
   in the first naming system of the nascent Internet,^[117][2] and was
   supposed to be an initial container domain for all then-existing
   ARPANET hosts. The next stage of development of the naming architecture
   foresaw the establishment of specific domains for other purposes based
   on certain requirements.^[118][2]

Reverse IP address mapping

   [[119]edit]

   In many applications the reverse of the name-to-address mapping is also
   required. The host receiving a service request may require the domain
   name of the originating computer, for example, to customize the
   service, or for verification purposes. This latter function, called
   [120]Reverse DNS lookup, is implemented in the major uses of the domain
   arpa: its subdomains in-addr.arpa for [121]Internet Protocol version 4,
   and ip6.arpa for [122]IPv6.

   Conceptually similar lookup and mapping functionality is provided by
   other subdomains of arpa for specific types of data.

Telephone number mapping

   [[123]edit]

   The domain e164.arpa provides a lookup function that retrieves
   information associated with [124]telephone numbers through the
   [125]ENUM service. This service may be used to obtain the name of a
   computer that is capable of routing telecommunication requests for a
   registered telephone number, or obtain an email address to contact the
   subscriber of a specific telephone number.

Residential networking

   [[126]edit]

   The domain name home.arpa was reserved by the Internet Engineering task
   force in May 2018 as a [127]special-use domain name for non-unique DNS
   services in residential networking, to avoid the use of the top-level
   domain home., which would require DNSSEC signatures.^[128][3] In
   addition, the use of home. led to domain name leakage to the Internet
   root name servers. The [129]authoritative name servers for home.arpa
   intercept locally unresolved queries for the domain and return
   addresses for certain [130]blackhole servers.

History

   [[131]edit]

   The [132]ARPANET, named for the [133]Advanced Research Projects Agency
   (ARPA), was launched in 1969, and is considered the earliest
   predecessor of the [134]Internet. The agency's name was adopted as the
   name for the first formal name space of the network after it had
   transitioned to [135]TCP/IP networking in January 1983.^[136][2] The
   name was used as a naming suffix for all then-existing ARPANET hosts.
   Hierarchical domain-style names were intended to support delegation of
   responsibility and authority for adding future hosts to the network.

   With the formal development of such a hierarchical naming system, the
   domain also became one of the inaugural members of a set of domain
   names for specific types of network members, namely [137]com for
   commercial users, [138]org for organizations, [139]edu for educational
   institutions, [140]gov for government entities, and [141]mil for
   networks of the United States military.^[142][4]

   It was expected that the use of arpa would be temporary and that the
   existing systems would be migrated to other domains.^[143][4] But arpa
   also provided e-mail addresses associated with the Network Information
   Center, which administered the naming system. After serving the
   transitional purpose, it proved impractical to remove the domain. The
   domain in-addr.arpa had been installed for [144]reverse DNS lookup of
   IP addresses.^[145][5]

   Originally, the IETF intended that new infrastructure databases would
   be created in the top-level domain [146]int. In May 2000, this policy
   was reversed and it was decided that the top-level domain int should be
   restricted to use by international organizations.^[147][6] Arpa was
   retained for its long-standing purpose, but its full name was changed
   to the Address and Routing Parameter Area, making the zone name a
   [148]backronym.^[149][7] Registrations of internet infrastructure
   services in [150].int made prior to this policy change, were optionally
   grandfathered in and not required to move to .arpa.

   In March 2010, zone arpa was secured with digital signatures within the
   [151]Domain Name System Security Extensions (DNSSEC).^[152][8]

Subdomains

   [[153]edit]

   Subdomains of arpa are created by resolution in the work groups of the
   Internet Engineering Task Force via the [154]Request for Comments
   process, and are maintained by the [155]Internet Assigned Numbers
   Authority (IANA). The DNS zone arpa has the following
   subdomains:^[156][9]^[157][10]

   Domain Purpose Authority document ([158]RFC)
   6tisch.arpa For IPv6 over the [159]Time Slotted Channel Hopping mode of
   [160]IEEE 802.15.4

   RFC [161]9031
   as112.arpa Sinking of DNS traffic for reverse IP address resolutions,
   misc.
   RFC [162]7535
   e164.arpa Mapping of [163]E.164 numbers to Internet [164]URIs
   RFC [165]6116
   eap-noob.arpa For the Nimble Out-Of-Band authentication method of the
   [166]Extensible Authentication Protocol framework
   RFC [167]9140
   home.arpa Residential networking
   RFC [168]8375
   in-addr.arpa Mapping of [169]IPv4 addresses to domain names
   RFC [170]1035
   ip6.arpa Mapping of [171]IPv6 addresses to domain names
   RFC [172]3152
   in-addr-servers.arpa Domains for authoritative DNS servers for the
   reverse lookup domains
   RFC [173]5855
   ip6-servers.arpa
   ipv4only.arpa Detection of DNS64 availability and NAT64 prefix
   RFC [174]7050
   iris.arpa Locating Internet registry information services
   RFC [175]4698
   ns.arpa Domain for hosting authoritative DNS servers for the .arpa
   domain
   RFC [176]9120
   resolver.arpa Domain for discovery of designated DNS resolvers
   RFC [177]9462
   uri.arpa Resolution of URIs and [178]URNs,
   according to the [179]Dynamic Delegation Discovery System
   RFC [180]3405
   urn.arpa
