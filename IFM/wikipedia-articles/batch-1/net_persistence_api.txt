   From Wikipedia, the free encyclopedia

   The .NET Persistence API, also referred to as NPA, is a persistence and
   [55]object–relational mapping (ORM) specification for the [56].NET
   framework.^[57][1]

   NPA is based on the [58]Java Persistence API (JPA), which is the
   standard persistence API in the [59]Java world. NPA follows JPA by
   providing a complete persistence API and a rich set of ORM
   features.^[60][2]^[61][3]

Motivation

   [[62]edit]

   The main purposes of the .NET Persistence API (NPA) are:^[63][2]
     * To provide a vendor-free persistence API for .NET, making switching
       from one persistence provider to another easier (avoiding
       [64]vendor lock-in).
     * To provide a cross-language persistence API by extending the
       popular [65]Java Persistence API (JPA) to all the .NET programming
       languages.

Technology

   [[66]edit]

   The main features of NPA include:^[67][4]^[68][5]
     * Object-oriented API for working against databases (usually RDBMS).
     * Query language, based on SQL, for retrieving data from the database
       in an object oriented manner.
     * Support of persisting [69]POCO (plain old CLR objects) objects
       (entities).
     * Two methods for marking classes as entity classes and for
       specifying other settings:
          + Using attributes – meta data is embedded in class definitions
            in the source code.
          + Using external XML – meta data is specified in external
            [70]XML resource files.

Implementations

   [[71]edit]

   NPA is a persistence specification. To use NPA an implementation of the
   specification is required. Persistence and ORM vendors can provide
   their own implementations of NPA.

   First implementation, NPA for [72]NHibernate, was released in December
   2011.^[73][6]^[74][7]
